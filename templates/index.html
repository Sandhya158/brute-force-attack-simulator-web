Two-Phase Attack Engine

Phase 1 — Smart Dictionary: generates a personalised wordlist from the target username: exact name, reversed, leet-speak mutations, common suffixes (123, @, 2024), capitalisation variants, then generic common passwords. Much smarter than a random wordlist.

Phase 2 — Brute Force: uses itertools.product(charset, repeat=n) to generate every possible combination. Equivalent to Hashcat's ?a mask attack. Charset options: digits (10), lowercase (26), lower+digits (36), full (70 chars).

CAPTCHA Auto-Solver

The simulator automatically solves the math CAPTCHA using regex (re.findall(r"\d+", question)). In real attacks, services like 2captcha charge ~$1 per 1000 CAPTCHAs. This demonstrates why simple CAPTCHAs are insufficient — only behaviour-based systems (reCAPTCHA v3) are effective.

Defence 1 — Progressive Delay (Exponential Backoff)

After each failed attempt the wait time doubles: 0.5s → 1s → 2s → 4s → 5s (capped). Slows brute force from ~1000 req/min to ~12 req/min without locking out the legitimate user.

delay = min(0.5 × 2^(failures-1), 5.0)

Defence 2 — Account Lockout

After 5 failed attempts the account locks for 2 minutes. Attacker must wait or move to the next account. Risk: DoS against legitimate users. Modern systems use soft lockout + CAPTCHA instead of hard lock.

Defence 3 — CAPTCHA Simulation

Triggered after 3 failures. The simulator auto-solves it using regex — demonstrating that simple arithmetic CAPTCHAs are trivially bypassed by any script. Real protection requires reCAPTCHA v3 (invisible, behaviour-based).

Defence 4 — No User Enumeration

Auth always returns "Invalid credentials" — never "User not found" or "Wrong password." This prevents attackers from confirming valid usernames before attempting passwords.

Defence 5 — Password Hashing

Passwords stored as SHA-256 hashes (educational). Even if the database leaks, attackers get hashes not plaintext. Production must use bcrypt or Argon2 with per-user salts and a high work factor to make offline cracking slow.

Defence 6 — Logging & SIEM

Every attempt is written to logs/session_*.json. A SIEM rule example: IF failed_logins > 10 in 60s from same IP → alert + block at WAF. Real tools: Splunk, ELK Stack, Wazuh.

Modern Hardening Checklist

  • ✔ Multi-factor authentication (most effective single control)
  • ✔ Adaptive authentication (risk-based, not just password)
  • ✔ Credential breach monitoring (Have I Been Pwned API)
  • ✔ Zero Trust network model
  • ✔ WAF + IP rate limiting (fail2ban, Cloudflare)
  • ✔ Privileged Access Workstations (PAW) for admins
